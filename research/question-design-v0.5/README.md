# 游格全库专属题设计

2026-10-30确认的范围是：每款12道作品专属题，另保留4道跨游戏题，必要时最多2道补问。题型以具体情境中的行动取舍为主；首批按8道行动题、4道体验回顾题编排。剧情可以入题；没有体验过的情境允许换题，不把未体验算成答案或低分。

全库目标是2,178条公开作品记录，而不是只处理用户测试到的原神。该数量含版本记录，是否可共享题目需要按实际玩法逐条核对；候选库尚未公开的作品在正式收录时补齐同样的设计检查。

## 逐款编写与核对

先为作品记录真实的活动、玩家会遇到的取舍、单人与多人模式、解锁进度以及版本区别。游戏商店标签只用于发现作品，不能代替玩法调查。优先读官方玩法介绍、开发者指南和更新说明，再用攻略与游戏资料库补足实际流程；社区整理内容标明来源性质。

每道专属题必须给出具体情境、四种可行做法、拟区分的动机以及解释边界。专有名词不等于设计质量：去掉名字后，若整套仍可直接移给其他游戏，需要重写。反过来，不能为表现独特而捏造游戏里不存在的行动。

12题应覆盖多种投入场景。行动题优先询问时间、资源、信息或目标发生取舍时先做什么；回顾题用于核对相近行为背后的不同理由。不要把一套题写成攻略考试，也不要让正确操作、道德判断、付费、可支配时间或游玩水平决定人格结果。

剧情题可以触及人物经历和分歧，但不能默认玩家能改写固定剧情，也不能直接把支持某个角色解释成现实善恶。NPC互动不能冒充真人社交；单人玩法中不存在的PvP不会硬塞进情境。

## 换题与模式范围

换题是换情境，不是第五个计分选项。正式卷仍需完成12道适用专属题和4道跨游戏题；正式答案只保留实际展示的题目及其版本。拒绝把未体验代填为“不喜欢”“不社交”或“不会”。

一个替代题仍有体验条件时，继续检查该条件；不能假设换一次就适用于所有玩家。首批原神的未联机替代题改问同好交流，若玩家也没有这类交流，仍需要另一条路径。不同模式之间也需独立设计，例如只玩大乱斗的人不能被迫答峡谷运营题。

首稿中33道缺少替代情境的问题已补写，换题、撤销、暂存和回看已经接入。每个已提供模式的每个题位，初始都有可用替代情境；全部可用情境都未体验时允许暂存，不强迫选择。逐款状态以coverage.json为准。替代题没有经过统计等值验证，报告按实际回答的情境解释。

## 计分与报告一起修订

草稿的proposed_signal保留编辑来源。运行版使用独立的0.5.0计分规则，同一称号在专属题中最多采用两个情境的贡献。旧报告固定读取攻略、剧透、重玩、Mod等题目的逻辑不再用于新答卷；新报告只引用实际展示并回答的题义。

不同游戏提供不同的活动机会。首稿中，CS2有9个选项拟指向精进，博德之门3有10个选项拟指向代入；这些次数本身不能证明某类玩家更常见。后续需检查全卷机会分布、替代路径、位置偏好和结论所需的多情境依据。单纯除以最高可得分，不能当作已经消除题包差异的证明。

新题义、计分与报告使用单独版本；旧答卷按旧题保留，修订过的专属题包保留不可覆盖的内容快照。首批已完成作者的来源与内容复核、模式和替代路径、计分机会限制及端到端报告检查。代码结构检查通过不等于题目质量或测量效果已由真人验证。

## 可重复生成

在项目根目录运行：

```powershell
python scripts/author_question_design_batch1.py
python scripts/build_question_packs_v05.py
python scripts/audit_question_design.py
python scripts/check_game_question_coverage.py
python scripts/update_question_rewrite_progress.py
python -m unittest tests.test_question_design_draft -v
python -m unittest tests.test_v05 -v
python -m unittest tests.test_question_coverage_audit -v
python -m unittest tests.test_question_batch02 -v
```

author_question_design_batch1.py生成基础首稿；build_question_packs_v05.py将基础稿与手写替代情境编译成当前题库，并保留历史版本。修改来源和解释后显式运行构建，不在玩家答题时生成内容。

question_batch02.py与question_batch03.py存放后续手写题目及其资料；question_authoring.py只序列化编辑已写好的题干、选项与信号，不根据游戏名或分类生成题目。新增批次均通过同一编译、快照、实际路由与替代路径检查。update_question_rewrite_progress.py只根据最新检查生成待办，不把排队视为编写完成。

check_game_question_coverage.py逐条调用网站默认取题路由，核对所有公开记录、已配置模式和旧候选兼容路径。检查对题干与选项去除游戏名并归一化，识别沿用的通用模板；同时核对逐款编写记录、题位和资料引用。它生成完整清单，区分“完整专属”“部分定制”和“通用模板”，不将4道允许保留的跨游戏题当成缺项，也不把覆盖检查等同于新的玩法事实或测量质量验证。
